## 2b. A security finding in my own new backup (found by the automated commit review, fixed the same hour)
The first nightly backup copied all of `data/`, which holds the dashboard's login record (`auth.json`), its cookie-signing secret (`auth_secret`), live sessions (`sessions.json`) and the user-studio list. My own check had searched only for names like "token" and ".env", so it reported 0 and I believed it. A leak of that archive would have allowed forging a dashboard session. VERIFIED on the server: the first archive (about 15 minutes old, never left the server, file mode 600 after writing) did contain those four files.
Fix: `data/` is now copied from an **allowlist** (a new file is left out until named), names with secret, session, auth, oauth, invite, cookie, password, tenant, token or credential are refused even inside allowed folders, the archive is created private from its first byte, the folder is mode 700, and `backups/` is in `.gitignore` and the never-commit list. The new archive was verified: 0 sensitive names, 552 files, 18.8 MB, same file name so the old one was replaced. A test covers each point. Lesson recorded: check a secret list by listing what is inside, not by grepping for the names I thought of.

## 3. Autopilot v2: what changed (all deployed)
- **Budget-aware starts:** a documentary is not started with less than $1.30 of the day's cap left, a Short or clip with less than $0.30. Starting one that cannot finish wasted its voice and pictures.
- **Nightly backup** (03:30 UTC): every video's record, claim ledger and caption words, the settings and `data/`; seven kept in `backups/`; no secrets, no videos. VERIFIED live after the security fix above: 552 files, 18.8 MB, 0 sensitive names inside. A new "Losing the records" row on the Risks card watches its age.
- **Daily report** (07:00 UTC): one plain-English entry in the activity feed: what was made, uploaded, coming in 48 hours, yesterday's spend, credit, and problems. VERIFIED live; its first report is accurate and readable.
- **Weekly cap** (`max_videos_per_week`, 0 = off): no new video for a slot that would be the Nth video out or scheduled in the 7 days before it. Off by default, so nothing changes until you choose a number.
- **Server-only settings** are now written down in `docs/SERVER_STATE.md` (generated by `python run.py state`, secrets hidden), so a rebuilt server can be set up the same way.
- **Holds stop the upload's schedule** (re-check), **uploaded videos keep their slot and approval** (earlier today), **a remade video is a new upload**, **picture variety, thin-source gate, retold-line removal, length cap, per-video illustration styles** (see the plan).
