# Review of gpu-router 0.1.0 for Story Studio (25 Nov 2026)

Source: ~/Downloads/gpu-router-plugin.zip (90,690 bytes, sha256 7bac0419d65b68dc...), 21 files plus a bundled `.git` (one commit, "Add gpu-router plugin", no remote). Extracted into a scratch folder, read in full, nothing from it run before reading. The bundled `.git` is not copied here. This branch is a candidate: it is NOT wired into the studio, nothing in the studio imports it, and Autopilot never calls it.

## What it is
A Claude Code plugin (`.claude-plugin/plugin.json`, a skill, two slash commands) plus a small Python package: a router that picks Kaggle (long jobs), Modal (short jobs) or CPU by job shape and remaining quota, an SQLite ledger of estimated quota use (weekly window from Saturday 00:00 UTC), Kaggle CLI wrappers, an optional Modal runner, optional Cloudflare R2 artifact storage and a notebook helper (skip finished shards, stop 45 minutes before the 12-hour cap, atomic writes).

## Checks
- Studio skill scanner (`vetskill.py`): no hidden download, no obfuscation, no tunnel or keep-alive. It calls the `kaggle` and `modal` CLIs, reads R2 keys from the environment, writes its ledger to ~/.gpu_router (all expected and read by hand). The 7 "high" findings were `.pyc` files made by this review's own test run, not in the zip.
- Its own 17 tests passed. They never used real CLI output.
- Its Kaggle status parser was run on real Kaggle CLI 2.2.5 output of 24 Nov 2026: `has status "KernelWorkerStatus.COMPLETE"` and `"...QUEUED"` both came out as `kernelworkerstatus`, neither finished nor failed, so `submit --wait` would poll until its 12.5-hour timeout.

## Problems found (0.1.0) and what 0.1.1 on this branch does
| # | Problem | 0.1.1 |
|---|---|---|
| 1 | Status parser broken on CLI 2.x (above) | `parse_status` reads `KernelWorkerStatus.X` and the older form; tests use the real strings |
| 2 | No accelerator sent on push (CLI 2.2.5 needs `--accelerator`; the P100 is retired) and no session cap | `push(accelerator=..., timeout_s=...)` sends `--accelerator NvidiaTeslaT4` / `TpuV5E8` and `-t` |
| 3 | Quota is a local estimate starting at zero (it would say 30 h left; the real account had 11.88 h used) | `real_quota()` reads `kaggle quota --format json`; the router never assumes more than Kaggle's own figure |
| 4 | Built to send video renders to Kaggle; no check of Kaggle's non-commercial terms | every job is commercial unless `--personal`; commercial jobs never go to Kaggle without `KAGGLE_COMMERCIAL_PERMISSION_REF` (Kaggle's written permission) |
| 5 | Modal (a paid service) chosen automatically, cost only estimated | Modal off unless `MODAL_ENABLED=1` |
| 6 | Kaggle username `shahed1475` (the GitHub name; the Kaggle account is different) in `.env.example` and the kernel template | placeholders |
| 7 | README and skill silent on the non-commercial clause | both state it |

Not changed: the notebook helper, the ledger, R2 storage (optional, needs your own R2 keys), the T4 and ffmpeg advice in the skill (advice, not verified here). Tests: 27 (17 original adapted to mark jobs personal and switch Modal on, 10 new).

## How it compares with what the studio already has
The studio's `kaggleworker.py` + `computerouter.py` (24 Nov 2026) already run real jobs on Kaggle T4s: a public-twin rule (the owner's file never uploaded, its maker's identical file proven by SHA-256), a data-class gate, verified retrieval against a manifest, recovery tested on hardware. gpu-router adds what the studio lacks: a multi-provider quota ledger, Modal, R2, and a shard/stage notebook helper for long renders. It does not have the studio's data-class gate, public-twin proof or output verification.

## Verdict
Useful ideas, not ready to be the studio's router. Before any production use: (1) Kaggle's written permission for commercial renders, or keep it to personal jobs; (2) decide whether Modal (paid) is wanted at all; (3) if adopted, reuse the studio's gate and verification rather than run two Kaggle paths side by side. This is a reading of terms and code, not legal advice.
